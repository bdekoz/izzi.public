## 3. Scope interpretation

**Tune** means tighten the level-set vocabulary against the reference
character: contour level spacing and offsets, source radius/strength/aspect
and angle relationships, `surface_exponent`, `boundary_attraction`, and the
degeneration amounts — plus the documented open items (degeneration
semantics and contour-layer composition).

**Extend** means additive helper builders in the existing API, no new spec
kinds:

- pattern helpers inspired by `L_PATTERN`: rings, lattices, and rotating
  source arrays with deterministic radii and phases;
- object helpers inspired by `L_OBJECT`: clustered source compositions that
  read as object-like membranes without copying archive contours;
- surface-texture helpers inspired by `L_SURFACE`: anisotropic source
  fields with shared tilt, aspect, and strength envelopes;
- `L_ADDITIONAL` informs only the exploration ranges.

No archive path data is extracted or embedded. The
`edge-archive-geometry-used` metadata remains `false`; the archive informs
spacing, density, envelope shapes, and texture character only.

## 4. How the sol-5.6 API round would run

Same loop as the guilloche and moire rounds, per the official OpenAI
documentation:

- Model `gpt-5.6-sol` via the Responses API, Flex processing (`service_tier:
  "flex"`, Batch rates), reasoning effort high on design turns and medium on
  mechanical edits.
- Tools: `apply_patch` for code changes and structured outputs for a
  per-package change manifest. `hosted_shell`, `code_interpreter`, and
  `image_generation` stay disabled (code changes only, no testing, no image
  production).
- Deliverable per turn: unified diffs plus a JSON manifest; a human or Codex
  applies and compiles locally.

## 6. Reference policy (no text, no numbers)

Each work package's prompt states the policy explicitly: the archive plates
are geometry references only. Sol-5.6 may use spacing, density, envelope
proportions, tilt relationships, and texture character; it must ignore any
text or numerals and must never extract or reproduce archive path data. The
archive is treated as a user-licensed set, so the independently-authored
provenance and `edge-archive-geometry-used=false` metadata are preserved
rather than weakened.

## 7. Compression / packaging recommendation

The billed unit is tokens, not bytes, so byte compression does not reduce
cost. The real optimizations are sampling, rasterizing, and caching.

**Sources — plain text, no compression.** Header plus example are about
36 KB (~11K tokens). Send them with `===== FILE:` separators, full fidelity.

**References — sample, rasterize with Ghostscript, then base64.** The archive
is PDF-compatible Illustrator, and `gpt-5.6-sol` vision input accepts raster
formats, not `.ai`:

- Rasterize a bounded sample with `gs -sDEVICE=png16m` at 1024 px on the
  long side: about five plates from `L_PATTERN`, six from `L_SURFACE`, five
  from `L_OBJECT`, and all five `L_ADDITIONAL` (~21 plates), roughly 960
  image tokens per plate at the 32px-patch rule and ~20K tokens for the set
  (about $0.05 per read at the Flex input rate).
- Sending all 102 plates is not justified (~98K tokens, about $0.24 per
  read) with little marginal guidance. Full-resolution zoom is allowed only
  for up to 3 plates per zoom turn and at most 6 zoom turns total.
- Transport: base64 data URLs for the sampled set; the Files API with
  `file_search` only if the same set must persist across many turns.

## 8. Cost estimate against the $50 balance

Official rates for `gpt-5.6-sol` (Flex/Batch processing, per 1M tokens):
input $2.50, cached input $0.25, cache writes $3.125, output $15.00.
Reasoning tokens are billed as output tokens.

| Scenario | Math | Total |
|---|---|---|
| 1. One-shot survey | input ~33K (cache write $0.10) + output ~15K ($0.23) | ~$0.33 |
| 2. Full round S1-S5, 30 turns, cached sample | first turn ~$0.33; turns 2-30: cached read (~$0.008) + deltas ~4K ($0.013) + output ~12K ($0.18) = ~$0.20 each = $5.8; 6 zoom turns ~$0.4 each = $2.4 | ~$8.50 |
| 3. Full round with Batch/Flex for mechanical bulk | about half of the per-turn fees at half rate | ~$5-6 |
| 4. Worst case: all 102 plates uncached every turn | 30 x (input ~$0.24 + output ~$0.30) | ~$16 |
| 5. Tight run: sampled, cached, Batch for bulk, 25 turns | smaller outputs | ~$4-5 |

Verdict: the recommended path (scenario 2 or 3) fits inside $50 with wide
margin, and even the worst case stays well under the balance because the
archive is smaller than the moiré set.
