## Recognition strategy

Use **full Whisper large-v3** as the proposed primary model, with standard
F16/F32 precision. Run **full large-v2** independently as a second hypothesis.
Keep their disagreements visible: model agreement is corroboration, not
proof of correctness. Treat this choice as a starting strategy to validate
on this recording, rather than a guarantee that one model wins every passage.

The installed large-v3-turbo model is useful for a preliminary index, if
needed, but will not be the sole final recognition pass. OpenAI describes
turbo as a faster large-v3 derivative with a small accuracy tradeoff; the
quality priority here warrants testing the full model. Integer quantization
and smaller/distilled substitutes are not the planned primary configuration.
[Whisper model documentation](https://github.com/openai/whisper#available-models-and-languages)

Keep the main passes sequential over the full recording using Whisper's
native long-form processing. Parallelize independent models, channel passes,
and disputed excerpts across hosts. Avoid splitting the main transcript into
unrelated short jobs merely to use more workers. The large-v3 model card
recommends sequential long-form inference when accuracy takes priority.
[Large-v3 long-form guidance](https://huggingface.co/openai/whisper-large-v3#chunked-long-form)

## Execution stages

1. **Freeze source and job manifest.** Recheck the measured source hash.
   Create `outputs/transcription/20260929_lisa_nakamura/` on rizal, with
   `source/`, `audio/`, `raw/`, `comparison/`, `review/`, and `deliveries/`.
   Retain the original WAV unchanged. Store probe output, channel analysis,
   input hash, model hashes, commands, host assignments, and status there.

2. **Inspect stereo and prepare ASR audio.** Listen to the opening,
   representative middle passages, quiet speech, and the ending in stereo,
   then each channel. Check speech placement, phase cancellation in a mix,
   speaker overlap, language, and noise. Produce 16 kHz PCM16 WAV derivatives
   for left, right, and an explicitly documented equal-weight mono mix.
   Preserve original speed, duration, and the zero-based source clock.
   Resample once from the original; retain stereo as the listening reference.
   Do not apply denoising, gating, compression, or gain changes to the
   baseline. A processed derivative is only a separately retained experiment
   for an excerpt that demonstrably benefits from it.

3. **Run a representative pilot.** Select approximately four minutes across
   the recording, including speaker changes, technical vocabulary, quiet
   speech, and overlap where present. Record exact source offsets. Listen
   and manually transcribe these windows for comparison. Test full large-v3
   on left, right, and mix; choose the baseline according to audible words
   recovered, not RMS alone. If channels contain complementary speech, run
   complete large-v3 channel passes as well as the mix and reconcile them
   against the stereo recording. Do not concatenate channel transcripts:
   shared speech must be deduplicated and simultaneous speech preserved.

4. **Validate decoding settings.** Start with beam size 5, initial
   temperature 0, and the runtime's documented fallback behavior, recorded
   explicitly in the receipt. Compare beam size **8** on the pilot rather
   than assuming a larger beam improves accuracy. The implementation found
   that the pinned runtime rejects beam 10: its maximum decoder count is 8.
   Preserve that failed experiment and use the supported setting. Inspect fallback-generated
   segments. Verify language from listening and detection; set it explicitly
   when appropriate. Use transcription, with translation disabled. Keep
   ordinary long-form context for the baseline; retry repeated or drifting
   passages with context reset. Run an unprompted baseline first. A second
   prompt may contain only a short spelling glossary grounded in audible
   names/terms or supplied reference material, not guessed dialogue.

5. **Run independent full passes.** Assign the chosen full large-v3 baseline
   to eureka and full large-v2 to ord. Use the same documented audio baseline
   so differences are interpretable. Additional full channel passes follow
   the pilot decision. Preserve complete raw text, JSON segments and
   available tokens, estimated timings, confidence-related diagnostics,
   logs, fallback events, and elapsed time. Do not replace raw hypotheses
   with a merged or edited transcript.

6. **Compare and retry uncertain passages.** Align hypotheses by time and
   words, using normalization only in comparison copies. Queue disagreements,
   unexplained gaps, repetitions, high no-speech scores, low average log
   probability, uncertain names, numbers, acronyms, short interjections,
   overlap, and chunk/window boundaries. Such scores prioritize listening;
   they are not calibrated guarantees of accuracy. Retry excerpts with
   5–10 seconds of context on each side, both channels where useful, and
   the alternative full model. Record source offsets and restore every
   excerpt's timings to the original clock. Use VAD to find candidate gaps
   and questionable silence; do not discard audio solely because VAD says
   it contains no speech. Listen before accepting new words in silence.
   Whisper can produce unsupported text, so even confident-looking passages
   require source checking. [Large-v3 limitations](https://huggingface.co/openai/whisper-large-v3#performance-and-limitations)

7. **Reconcile text and speakers against audio.** Build a chronological
   verbatim transcript. Preserve spoken repetitions, false starts, fillers,
   and meaningful laughter or other vocal events with consistent notation.
   Add punctuation for readability without paraphrasing or correcting the
   speaker's claims. Use neutral `SPEAKER_01`, `SPEAKER_02`, etc., until
   identity is supported by introductions or human confirmation. Mark
   simultaneous speech explicitly. Channel number is not a speaker label.
   Use `[inaudible HH:MM:SS–HH:MM:SS]` or a documented uncertainty label
   instead of inventing words. Record each material correction, timestamp,
   evidence, and reviewer; unresolved passages remain listed.

8. **Review the entire recording.** A listener checks all 34:43 against the
   assembled text, including the opening, ending, quiet turns, interjections,
   and passages where both models agree. Revisit every flagged excerpt.
   If that review has not happened, deliver an explicitly marked **ASR draft
   pending complete listening review**, not a fully verified transcript.
   Calculate pilot word error rate only against the manually checked pilot
   reference; do not report model disagreement as full-recording WER.

9. **Finalize timing and verify delivery.** Check segment timestamps against
   speech, allow overlap for simultaneous speakers, and retain meaningful
   gaps instead of filling silence. Whisper token/word timings, if exported,
   are estimates; flag approximate or uncertain boundaries. Any additional
   alignment step must use the corrected transcript and be documented as a
   separate tool. Export final text and structured data, validate hashes and
   complete coverage, and copy verified deliveries to rizal. Atomically
   publish final files only after their verification receipt is written.

## Queue, recovery, and timing

Rizal owns the manifest and dependency queue. Each ASR job has a stable key
containing the source/derivative hash, model hash, runtime revision, language,
decoding parameters, channel, and source time range. Use per-job locks,
durable logs, temporary output paths, and validated completion receipts.
Workers can claim compatible pending jobs; only hosts with a tested backend
may claim GPU jobs. Start with one model process per GPU and measure before
increasing concurrency. Avoid CPU thread oversubscription.

Use authenticated resumable transfers and verify derivative/model hashes.
Ord and eureka can exchange files directly using the documented USB4 link;
rizal remains the control plane and final transcript location. Reuse completed
jobs after restart. A failed full-file job may need to rerun unless the
selected runner demonstrably supports validated continuation; partial JSON
alone is not a checkpoint. Do not omit a difficult passage to finish a job.

Measure model load time and real-time factor on the pilot before quoting
completion time. For each full pass, use
`estimated_seconds = load_seconds + measured_RTF × 2083.356735`.
For parallel hosts, use each host's total assigned workload and the longest
dependency path, then add retries, reconciliation, and listening review.
The complete listening review itself requires at least about 35 minutes at
normal speed, before corrections. Preparation and model provisioning are
separate from inference time; 96 GB of RAM allocated to eureka's GPU is not
a speed estimate. This allocation is distinct from its approximately
31.1 GiB host-visible memory reported by `/proc/meminfo`.
