## Verification and Doxygen re-validation

After all DX9 edits, run this gate in order and stop on any failure:

1. `make check-prefixes` — filename/prefix audit stays CANONICAL-READY.
2. `rg -n 'Supercut usage'` shows the section only in
   `docs/visual_workflow.md` (plus this plan), and no leftover copy in
   `docs/workflows.md`; any other page linking the `#supercut-usage` anchor
   is repointed.
3. Doxygen staleness check: `scripts/publish-public-mirror.sh --regen-doxygen
   --dry-run` (or the equivalent make target) to see whether `docs/html/`
   changes; the workflow-doc move and README edits can invalidate Doxygen
   page links, so regenerate `docs/html/` with `SOURCE_BROWSER = NO` if the
   dry-run reports drift.
4. `scripts/check-public-mirror-links.py` full audit and
   `--html-only` audit of `docs/html/` both report 0 issues (fail-closed;
   extend the surgery rules only if a new link legitimately needs mapping).
5. Mirror refresh dry-run: `scripts/publish-public-mirror.sh --dry-run` and
   confirm the generative-family `.html` pages carry the new headings and
   stripped File cells, and the Supercut/anchor links resolve.
6. After approval to publish: `scripts/publish-public-mirror.sh
   [--regen-doxygen] --push` (izzi and izzi.public pushes are separate
   authorization gates per the standing conventions).
