## Proposal — integrate and improve the supercut pipeline (2026-08-21)

Status: `PROPOSAL — AWAITING-HUMAN-APPROVAL` (planning only; no code changes,
no provider spend, no commit/push performed)

### 1. Verified current behavior

`MiL.git/scripts/ffmpeg-supercut-123-dupe.sh` takes four positional
arguments — input file, start time, clip length, cut number — and produces
two outputs per cut under `./output/`:

- `ssk.orig/FILE-cut-N.mkv` — a fast-seek, stream-copy cut (keyframe-aligned,
  original codecs);
- `ssk.1080p/FILE-cut-N-1080p.1.mkv` — the same cut scaled and padded to
  1920×1080 with `libx264 -qp 18` and `libmp3lame -b:a 384k`.

It created the corpus at
`resources.rizal/blade-runner/output/`: five original cuts
(`Blade.Runner.Final-Cut.4k-cut-{1..5}.mkv`) and five 1080p cuts
(`…-1080p.1.mkv`), two of which are the `time-to-die-ai/seed-video-corpus`
inputs. A `.2` output variable exists but is never used.

### 2. Assessment

The script is a workable 2019-era one-shot helper, but it predates izzi's
current discipline. Concrete gaps:

1. No validation or quoting of `SBEGIN`/`SLEN`/`CUTN`; no probe of the input
   before cutting; ffmpeg exit codes and `mkdir` failures are ignored, so a
   partial file can silently stand in for a good cut.
2. Fast seek + stream copy means cuts land on keyframes and may drift from
   the requested start; there is no frame-accurate mode and no post-cut
   verification of duration or geometry.
3. No manifest or hashes, so the corpus has no recorded provenance — a gap
   against izzi's SHA-256-bound review discipline.
4. The archive tier uses lossy MP3 audio; the 1080p tier has no `setsar=1`,
   fps normalization, color metadata, or `-avoid_negative_ts` handling.
5. No dry-run, idempotent resume, atomic writes, cleanup of partial files,
   batch mode, or tests; the `.2` path is dead code.

### 3. Integration form — recommendation

Primary: a Python script `scripts/izzi-supercut.py`. ffmpeg is already an
external dependency, and Python matches the repo's existing orchestration
(`scripts/resources_path.py`, the `render-*.py` / `check-*.py` family) and
makes validation, manifests, batch specs, and tests cheap.

Optional companion: a small header `src/izzi-media-supercut.h` if the round
should also expose the cut spec and manifest as izzi C++ types (mirroring
`scene_spec`/`resource_budget`). It is not required for correctness.

Decision point for approval: Python-only (recommended) versus Python plus
the C++ header contract.
