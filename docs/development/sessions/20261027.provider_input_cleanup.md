## Deployment and staging lifecycle

The Pages workflow runs Node 22, the publication/staging safeguard tests, and
`node scripts/check-review-site.mjs` before Jekyll builds or uploads a site.
The build manifest binds the staging-manifest hash and records its active
count and bytes. Registered permanent review assets, including three older
Duotone Noir frames under the provider-input prefix, retain their existing
catalog/hash checks. An HTML link alone cannot exempt a temporary input.

The site CLI `scripts/stage-provider-input.mjs` implements:

1. `stage`: verify format and size, archive exact bytes outside the site, then
   publish an input with an owner, purpose, job, hash, archive receipt and expiry.
2. `submit`: record the stable request idempotency key before a provider call.
   This protects a submission whose network response is lost from automatic
   expiry cleanup.
3. `attach`: record the returned provider task ID.
4. `finish`: after confirmed completion, failure or cancellation, verify the
   archive again, remove the unchanged public input, and retain its receipt.
5. `expire`: remove expired, unused inputs after archive verification.
   Submitting/submitted inputs require an explicit terminal result.

Each command regenerates the build manifest and runs the full site checker.
An error restores the public files and manifests; content-addressed archive
copies remain. A lock prevents overlapping CLI mutations. Paths cannot escape
the staging root or traverse symlinks. Defaults are 24 hours of staging and a
maximum seven-day lifetime. Expiry is checked during operations and deployment;
there is no scheduled cleanup service. Unresolved expired jobs block deployment
until their outcome is established and the input is retired.

`resume-pilot-production.py`
uses this lifecycle. It commits only managed paths, checks commit/push results,
verifies the live input hash before use, and verifies HTTP 404/410 after cleanup.
Continuation frames are staged when the consuming segment starts; final frames
and frames held at a credit gate remain local. A confirmed failed task stops
for review. Timeouts preserve the input and task ID; resuming polls that task
instead of buying another. An ambiguous initial submission retries the saved
request with the same idempotency key.

Existing configs can set `pilot.start_frame_source`, `provider_archive_root`
and `provider_input_ttl_hours`. The old default Frogtown start URL resolves to
its canonical local frame for managed staging. `pilot.site_repo` must point to
a current site checkout containing the new CLI. The original site checkout
at `/home/bkoz/src/situationshipin.space` was left unchanged; the active worktree
for this publication is `/tmp/izzi-workflow-revisions-site`.
