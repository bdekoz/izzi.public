### Movie adapter

`scripts/video_glitch_movie.py` implements an explicit **hybrid compositor**.
It applies the seven families directly to the canonical movie pixels.
Phase 1's native path backend remains intact. This adapter shares the family
parameter vocabulary, normalized geometry units, and exact
`splitmix64-counter-v1` arithmetic; it does not call the native path renderer
or claim to reconstruct vectors from a video.

- Every plate receives one family, cycling through all seven. Each 80-second
  reel includes eight plates and all seven families.
- Seed **20260927** derives a stable seed per plate. Effects rise over the
  first five seconds, hold, then recover over the last two seconds with a
  smoothstep envelope. Copy/wear/echo counts are integers. Every frame's
  source index, family, seed, envelope, and resolved parameters are logged.
- Tracking and copy jitter use disjoint 120-band crops; sync line pairing
  uses 240 bands. Geometric contours, lines, circles, and translated image
  instances provide wear, dropout, echoes, and satellite noise.
- Each VHS transfer operates on the previous transfer result. Three shifted
  image taps approximate echo spread. The canary checks that eight direct
  passes exactly equal three passes followed by passes four through eight.
- Composite color is explicitly raster-channel registration with geometric
  edge marks. It is an artistic interpretation, not a composite signal
  decoder. Its `leakage` field retains the Phase 1 reference value; this
  adapter's marks use fixed paint. Scratch width is fixed at two output
  pixels in this first movie implementation.
- The zero-strength frame preserves source pixels exactly. Repeated samples
  in a different evaluation order reproduce their hashes.

## Stages 1–4 — native implementation

Public headers are `src/izzi-svg-video-glitch.h` and
`src/izzi-svg-video-glitch-json.h`, in namespace `svg::video_glitch`.
The contract is **`izzi.video-glitch/1`**. Core operations work on editable
native strokes and points; decoding and encoding remain in the Python adapter.

The interface supplies typed parameters, event windows with rational timing,
smooth attack/release, operation ordering, strict JSON parsing, counter-based
noise, resource limits, `sample()`, `apply_vector()`, `copy_pass()`, and SVG
serialization. Unsupported targets/backends fail explicitly. Noise is pinned
to `splitmix64-counter-v1`, with stable FNV-1a effect identities.

### Copy history and practical limits

Generation zero is an identity operation. Increasing the copy count preserves
the preceding passes. Pass number, effect identity, seed, and content time
determine the new error. Registration, line displacement, dropout, opacity
loss, and echo variance act on each actual previous result. An invariant test
compares eight direct passes with three passes followed by passes four to eight.

Echo variance is serialized as three weighted translated vector taps. This is
a declared approximation to spread, not a photographic convolution. Dropout
and erosion act on resolved polyline segments, so source tessellation affects
the smallest damage. Tracking uses 120 bands; line pairing uses 240. Tracking
and satellite marks use a 30 Hz noise clock; transient dust uses 6 Hz.

The default limits are 32 passes, 60,000 paths, 2,000,000 points, and 64 MiB
SVG. Invisible sync-wrap copies are removed before the path-budget check.
The renderer caches completed family chapters using executable, renderer,
recipe, and output hashes. Intermediate copy scenes are not persisted; the
bounded native copy calculation is performed for each requested frame.

### Implementation choices relative to the proposal

- One `examples/video-glitch-plates.cc` driver produces seven separate plates
  and frame streams. This replaces the proposed collection of per-family
  `.cc` files and keeps the source scene and comparison conventions consistent.
- The review chapters use parameter holds. Event attack/release is available
  in the API; the delivered sweep is not a separate onset/hold/recovery film.
- The header implements a small smooth ramp directly, avoiding a dependency
  on the legacy movement document interface. Existing `izzi.movement/1`
  documents remain compatible.
- The implemented backend is `vector_geometry`, with a `vector` target.
  Movie composition demonstrates a native layer over the decoded picture.
  Physical field sampling, arbitrary raster-picture distortion, full
  PAL/NTSC/RF reconstruction, and optional gate weave remain extensions.
- Color leakage and satellite link margin are artistic controls. No calibrated
  carrier-to-noise ratio or photographic chroma decoder is claimed. Historical
  primary sources and the mechanism distinctions remain in the approved plan.

ranges and direct C++ use. Required local tools are a C++20 compiler,
RapidJSON, FFmpeg, Cairo, librsvg, and Python with PyGObject, lxml, NumPy, and
Pillow. No model inference or GPU service is required.

make video-glitch-check

  --integration-source outputs/ai-runner/visual/arx1-sdr-1920x800.mkv
