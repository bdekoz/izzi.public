# Paired-triangle count/share matrices

This implements Approach 2 from the [Fuller chart analysis](20260915.buckminister_fuller_archive_1.md#approach-2--place-by-metric-matrix-of-paired-triangles): geographic features form rows, network metrics form columns, and each rhombus contains a count triangle and a percentage triangle.

Open the Olympics Week 1 browser example, standalone SVG, or selected records. The browser example works offline and includes zoom, keyboard/pointer inspection, and a horizontally scrollable exact-value table. At narrow widths, scroll the chart or use the table instead of shrinking the text to fit the screen.

## Read the chart

- Upper-left, downward-pointing triangle: count. Blue intensity uses `log1p(count) / log1p(maximum displayed count)` across all displayed rows and columns. Its legend shows the corresponding count values.
- Lower-right, upward-pointing triangle: `100 × count / row_total`. Gold intensity uses a fixed 0–100% scale. The total column's lower triangle is unused and labeled `total`.
- Triangle areas are constant. They do not represent proportions of a partition. Network categories can overlap and their percentages must not be added.
- Explicit zero remains `0` or `0.0%`. Positive shares below 0.1% display `<0.1%`. Missing values and undefined shares are `N/A`, with hatching. Exact counts and four-decimal percentages are available in the table and cell detail.
- Rows are H3 features, not city totals or unique people. The city and country text are labels; the full H3 identifier distinguishes repeated labels.

The count scale is computed from the selected rows. Two plates with different selections may therefore have different count scales; consult their legends. Percentage scales remain fixed. Dark text is used on light marks and white text on dark marks. Triangle orientation, numerical labels, and the table provide alternatives to reading color.

## Build and reproduce

Requirements: CMake 3.20+, a C++20 compiler, and RapidJSON headers. The renderer is built when CMake finds RapidJSON. Network access is needed only to download the example source; rendering uses local input and has no network dependencies.

From the repository root:

```sh
cmake -S . -B build/count-share-matrix -DBUILD_TESTING=ON
cmake --build build/count-share-matrix \
  --target izzi_geojson_matrix_render izzi_count_share_matrix -j2
ctest --test-dir build/count-share-matrix \
  -R '^visualization.count-share-matrix$' --output-on-failure

curl -fsSL \
  'https://raw.githubusercontent.com/alpha60-devops/alpha60-results-sports/main/data/olympics-2026-week-00001.geojson.gz' \
  -o build/count-share-matrix/olympics-week1.geojson.gz

gzip -dc build/count-share-matrix/olympics-week1.geojson.gz |
  build/count-share-matrix/izzi_geojson_matrix_render - \
    build/count-share-matrix/olympics-week1-matrix \
    --rows 12 \
    --source 'https://raw.githubusercontent.com/alpha60-devops/alpha60-results-sports/main/data/olympics-2026-week-00001.geojson.gz'
```

The command emits three files at the requested output stem:

| Extension | Contents |
| --- | --- |
| `.svg` | Standalone chart with embedded Atkinson Hyperlegible fonts, image title/description, per-cell titles, exact values in accessible labels, and stable row/metric attributes |
| `.html` | The same SVG, zoom and cell detail controls, exact-value table, source and scope metadata |
| `.json` | `izzi.count-share-matrix-review/1` selected-record receipt; counts remain integers, H3 IDs are strings, missing values remain null |

The receipt is an output for inspection, not an alternative input schema. The CLI reads the source GeoJSON. It creates output directories and replaces files at the explicitly supplied stem; use a new stem to retain earlier renders.

The inspected compressed input has SHA-256 `be454f56f75dbe348c77d2918c45e38df37f1e7d405288f9a3d189bc98667fd7`. It declares data version `20260628`, 2026-02-08 through 2026-02-14 **partial**, and H3 resolution 5. The source URL is mutable; a different digest may produce a different plate. The checked-in receipt records the selected values from this run without adding the 22 MB decompressed source to the repository.

### CLI options

```text
izzi_geojson_matrix_render input.geojson|- output-stem
    [--rows 12]
    [--category downloaders|uploaders]
    [--minimum-size 0]
    [--row-shift 24]
    [--source URL]
```

`--rows` accepts 1–1000 and defaults to 12. Rows sort by descending selected-category `size`, then lexicographically by H3 string for ties; missing totals sort last. `--minimum-size` excludes missing totals when positive. The figure describes both the eligible and selected row counts. Use modest selections for legibility.

`--row-shift 0` aligns row anchors; the paired rhombi remain triangular. Positive or negative shifts create an oblique arrangement. The renderer computes extra canvas space for either direction. The built-in geometry accepts shifts up to one cell side in magnitude. The current CLI supports individual H3 features only; it does not silently aggregate cities or countries.

## C++ API

[`izzi-svg-graphs-matrix.h`](../../html/izzi-svg-graphs-matrix_8h.html) supplies a reusable count/share model and pure SVG/table serialization. It does not depend on RapidJSON and does not alter `graph_document`, its schemas, or the existing line/bar/chord APIs.

```cpp
#include <izzi-svg-graphs-matrix.h>

svg::count_share_matrix matrix;
matrix.title = "Network characteristics";
matrix.period = "Specified observation window";
matrix.source = "Source URI";
matrix.scope = "Selected H3 features";
matrix.metrics = {{"size", "Size (total)"}, {"vpn", "VPN"}};
// Populate rows from reviewed data; counts[0] is each row's denominator.
// Each row has: id, label, detail, vector<optional<uint64_t>> counts.

svg::matrix_options options;
options.row_shift = 24;
const std::string image = svg::render_count_share_matrix(matrix, options);
const std::string table = svg::render_count_share_table(matrix);
```

`matrix_share(row, column)` returns an optional fraction, not a percentage; it is undefined for column zero, a missing input, or a zero denominator. `validate_count_share_matrix` checks IDs, row widths, geometry limits, and each membership against its denominator. It intentionally allows membership sums to exceed the denominator. Both render functions validate their input and return strings without implicit file writes.

The layout uses horizontal column steps of one cell side and configurable row-anchor shifts. Each cell has vertices `(x,y)`, `(x+a,y)`, `(x+1.5a,y+h)`, `(x+0.5a,y+h)`, with `h=sqrt(3)*a/2`. Its diagonal splits it into two equilateral triangles. Typography is positioned separately and remains horizontal. Default side length is 144 SVG units, with a 14-unit row gap. Long visual labels are abbreviated on UTF-8 boundaries; their full text remains in cell descriptions and the table.

The matrix uses fixed decimal coordinates when calling `polygon_element`, because its default `setprecision(2)` otherwise rounds large coordinates to two significant digits. This adjustment is local to the new renderer and does not change existing polygon outputs.

[`izzi-svg-matrix-geojson.h`](../../html/izzi-svg-matrix-geojson_8h.html) adds the Alpha60 adapter:

```cpp
#include <izzi-svg-matrix-geojson.h>

// root is a parsed rapidjson::Document, retaining integer precision.
svg::geojson_matrix_options selection;
selection.category = "downloaders";
selection.limit = 12;
selection.source = "The source GeoJSON URL";
const auto result = svg::matrix_from_geojson(root, selection);
const auto svg_text = svg::render_count_share_matrix(result.matrix);
const auto receipt = svg::matrix_review_json(result);
```

The adapter reads only `root.features`, requires a hexagon partition and valid Point geometry, and preserves feature grain. Nested `collection_week_by_btiha` collections are ignored. It accepts H3 identifiers as lossless unsigned JSON integers or nonempty strings. Do not pass the data through a JavaScript Number-based parser before the adapter; the source's numeric H3 IDs exceed JavaScript's safe integer range.

Counts must be nonnegative JSON integers or null/missing. Negative, fractional, string, or over-denominator values are rejected with a diagnostic. The adapter validates the entire top-level collection before ranking or filtering, so invalid hidden rows cannot silently disappear. Missing category objects become missing fields; malformed non-object categories are rejected. This is type/range validation, not verification of the upstream classification or counting methodology.

The review JSON is a small, separately named output format, not an extension to `izzi.graph/1` or a promised interchange schema for the existing visualization facade. The original feature coordinates are validated but not retained in the selected-record receipt; this matrix is not a geographic map.

## Tests and limitations

`visualization.count-share-matrix` covers lossless and adjacent H3 IDs, repeated city labels, ignored nested collections, valid overlapping memberships, correct denominators, zero/missing/null distinctions, empty selections, top-N filtering, rejection of invalid counts and identifiers, XML escaping, deterministic output, negative row shifts, and fixed-decimal polygon coordinates. Its second translation unit also exercises header-only linkage. CMake automatically includes both new public headers in the self-containment checks and install manifest.

Two optional checks exercise the real Olympics artifact, independently of the C++ calculations:

```sh
# Pass the decompressed source and the generated receipt/SVG.
python3 tests/count-share-matrix-artifact.py input.geojson chart.json chart.svg

# Node 22+ and Chrome; CHROME can select another Chromium executable.
# Checks the default 12-row example at 1440px and 390px and saves screenshots.
node tests/count-share-matrix-browser.mjs chart.html build/matrix-browser-check
```

The artifact check verifies all selected counts and lossless H3 IDs against the source, recomputes shares, checks viewport containment, and checks equal triangle area. The browser check verifies keyboard inspection, zoom, page overflow, label bounding boxes, and actual text/fill contrast. The checked-in example passed with 120 cells, 240 equal-area triangles, no detected clipping or page overflow, and minimum text contrast 4.59:1. The 390px table and chart intentionally scroll horizontally. SVG XML validation and the existing histogram/bar regression test also passed. These checks do not establish upstream sampling or classification accuracy.

The rendered Olympics artifact contains 12 selected H3 features and all ten network columns. Exact values can be checked against the adjacent JSON and the original source. Count/share comparisons describe this partial observation window and the producer's reported counts, not country population rates or unique persons. The implementation provides neither cross-week deduplication nor geographic aggregation, per-media selection, joint-category inference, or a transfer graph.
