## Treatment

Each ten-second plate receives one family, cycling in this order:

1. Film damage: accumulated wear, irregular erosion, scratches and dust.
2. VHS generation: recursive transfer loss, disjoint band jitter, dropouts
   and three-tap image echoes.
3. VHS tracking: a moving tracking band, tears and noise marks.
4. Sync loss: line pairing, vertical roll and blanking.
5. Ghost: moving, delayed image copies.
6. Composite color: recursive channel registration and colored edge marks.
7. Satellite threshold: changing streaks and mixed-polarity impulses.

The existing source motion remains the input to every effect. This is the
existing `hybrid_composite` movie adapter; it applies geometric controls to
decoded movie pixels. The native vector signal-study backend remains a
separate capability.

The established family controls are retained, including actual recursive
copy counts up to sixteen. Seed `20260929` derives an independent seed per
plate using `splitmix64-counter-v1`. Effect strength follows
`smoothstep(min(local_frame / 150, (289 - local_frame) / 60, 1))`, with
smoothstep clamping its input to `[0,1]`. Effects peak after five seconds,
recover during the exit, and are zero at frames **289–299**. Those eleven
frames preserve the source's completely clear background.

New scratch, dust, tracking, chroma and impulse paints use named Izzi hues;
the backing is ivory. The exact palette is recorded in the manifest.
Raster interpolation, blending, channel misregistration and codec conversion
produce derived pixel colors, as expected when processing the moving input.
Optional palette, recovery-frame and seed controls leave the adapter's old
defaults unchanged; canary checks compare those defaults against the
committed earlier implementation.

## Rebuild

From the repository root:

```sh
python3 scripts/render-moire-glitch-movie.py canary --workers 4
python3 scripts/render-moire-glitch-movie.py render --workers 4
python3 scripts/render-moire-glitch-movie.py package
python3 scripts/render-moire-glitch-movie.py verify
```

The renderer uses the frozen source-production snapshot and checks the input
movie hash. Rendered parts are reusable only while the implementation,
manifest and encoded-file hashes match their receipts. Defaults and
historical recipe details remain documented in the
[video-glitch guide](../../generative_movement/video-glitch.md).
