# Screen Glitch documentation, second pass — 2026-10-01

## Investigation

The entry guide is `docs/generative_movement/screen-glitch.md`. The assessment
compared it with the screen composition/JSON headers, receiver implementation,
native worker, film and video guides, navigation, generated catalog, Doxygen
output and public-mirror builder. The original C++ snippet compiled and ran
after wrapping its statements in `main()`; JSON round-trip succeeded. The
generated review catalog contained the stated 38 media forms and 605 controls.
All seven original entry-guide links resolved in the working checkout.

The README's Movement destination omitted Screen Glitch and film decay.
The entry guide lacked a complete executable example, build instructions,
saved output, a JSON recipe/schema, a parameter reference, a moving-source
example and practical receipt/error guidance. Checked-in Doxygen had no
Screen Glitch reference pages. The public-mirror dry run reported 728 issues
across the repository: this entry guide contributed missing links to the
excluded evidence catalog and two excluded reel files. Live GitHub/Pages
fetches were unavailable, so the assessment establishes local and mirror-build
state, not the contents of the deployed website.

## Analysis

**Human decision:** this is documentation integration. Do not assume or plan
an API deprecation, replacement or migration. Any transition requires an
explicit human decision. Keep both versioned engine interfaces documented.

Screen Glitch should be the composition entry point, with film and analog
engine details linked underneath. All film-specific documentation, including
the historical `/1` `film_damage` controls, study and interface, belongs in
the existing film guide's interface, timing, controls, rendering and review
sections. The video guide should cover tape, television and satellite effects.
The seven-family generator and delivery remain seven-family artifacts; moving
documentation does not change their recipes or rendered output.

Native descriptors are the authority for catalog controls. Generate the public
reference from those descriptors rather than inventing a second list of 605
controls. Distinguish catalog form overrides from complete composition JSON,
and native control defaults from named preset defaults. JSON Schema supports
authoring checks; the native parser remains responsible for duplicate keys,
cross-field rules, nested engine semantics and runtime capabilities.

Local render artifacts are useful evidence but are excluded from the curated
public mirror. Public documentation needs portable examples, evidence and
references. Regeneration must preserve the mirror's exclusion of source
listings and its check for genuinely broken included documentation links.

also remain native checks. This boundary is documented explicitly.

### Validation results

- The stationary entry-guide example, executable still/moving-source example,
  and integrated `/1` film API example compile and run. JSON round-trip and
  saved SVG/receipt outputs succeed.
- The moving-source receipt records local time **2.1 s** and an earlier
  requested source time **1.966667 s**. The native worker's source-sequence
  example holds the earlier SVG, and a complete-document wrapper renders and
  writes a receipt at normalized progress 0.25.
- Draft 2020-12 schema validation accepts the two shipped/example recipes and
  native-emitted recipes for all six implemented operation types. It rejects
  unknown/missing fields, out-of-range enums, mismatched parameter shapes,
  fractional counts and unsupported codec operations. Six native rejection
  checks cover duplicate keys, invalid enum, burst-width coupling, mismatched
  operations, repeated IDs and unavailable codecs.
- `ctest --test-dir build/cmake --output-on-failure -R '^screen-glitch.contract$'`
  passes after rebuilding the worker and contract executable.
- Both `package-contract` tests pass, including canonical/relocated consumers
  and exact installed inventory. The relocated prefix contains the new schema.
- `public-mirror.links` passes three regression tests covering excluded
  artifacts versus missing included targets, code versus Markdown links,
  and source-listing removal versus the `native_source` reference page.
- Generated catalog `--check`, source ownership audit, 138 local link/anchor
  checks, focused Doxygen link audit, public-snapshot audit, shell syntax and
  `git diff --check` pass. CCache was disabled for builds because its default
  cache directory is outside the writable workspace.

Verification does not claim calibrated RF/codec behavior or new artistic
