## 3. Scope interpretation

**Tune** means one additive, opt-in builder per motif (GX1/GX2 share one
parameterized builder since both briefs describe the same red vertical-stack
vignette motif). Existing defaults, accepted plate filenames, and stage-4
outputs stay byte-stable.

**Extend** means five additive builders in `src/izzi-svg-guilloche.h`:

- `make_dutch_stack_vignette` — GX1/GX2: a vertical stack of distinct
  guilloche bands (e.g., rosette/band/sunburst tiers) under an annular
  vignette; one red plate.
- `make_dutch_quad_medallion` — GX3: a center radiating circle, satellite
  circles above/below, and satellite ray polygons left/right with ripple
  modulation; four plates (black, blue, white, orange).
- `make_dutch_hexagon_field` — GX4 group 1: four rows of repeating hexagon
  cells; two plates (gray, brown).
- `make_dutch_mandala` — GX4 group 2: a mandala with vignette; three plates
  (gray, dark red, white).
- `make_dutch_yellow_triptych` — GX5: halftone dot field, gradient circle,
  and sunflower motif inside a bounded rectangle; two plates (gray, brown).

Each color is a separate plate, so the renderer emits one SVG `<g>` layer per
color. Enum/schema evolution is authorized where the new builders need a
`pattern_family` value or scene-JSON spelling.

**Review plate (authorized):** six separate 3×5 plates — one per group
(GX1, GX2, GX3, GX4-group-1, GX4-group-2, GX5). Each plate is one grid SVG
plus 15 per-cell SVGs, for 96 SVGs total.

## 6. Reference-image policy (no text, no numbers)

Unchanged from stage 4: the photographs are geometry/color references only.
Sol-5.6 may use curve structure, spacing, proportions, layer separation, and
color; it must ignore and never reproduce lettering, numerals, serials, or
signatures. Crops are used only to isolate the described motifs; no image
output is produced and no path data is extracted from the photographs.

## 7. Compression / packaging recommendation

- Sources: no compression; plain text with `// ==== FILE:` separators
  (unchanged from stage 4; the bundle grows by the stage-5 example and docs).
- References: crop to the described motif, then resize to 1024 px on the
  short side (JPEG q82) and send as base64 in the prompt prefix. GX4 needs
  two crops (top hexagon band; lower-right mandala), GX5 one crop (the
  yellow bounded rectangle). Full-resolution zoom is capped at 3 zoom turns.
- The reads are independent, so they are submitted as one Batch file where
  turnaround allows (six requests, half-rate, parallel); Flex only if a read
  must return immediately.

## 8. Cost estimate against the $50 balance

Official `gpt-5.6-sol` rates (standard: input $5.00 / cached $0.50 / cache
writes $6.25 / output $30.00 per 1M; Batch/Flex halve them; >272K input bills
2×/1.5×). Reasoning tokens bill as output.

| Scenario | Math | Total |
|---|---|---|
| 1. Six image reads (1024 px crops, Batch/Flex) | 6 × (~3K in + ~1K out) | ~$0.20-0.30 |
| 2. One-shot survey (K1+K2) | input ~120K ($0.30-0.60) + output ~25K ($0.38-0.75) | ~$1.00-1.35 |
| 3. Full round K1-K4, ~15 cached turns + 2-3 zoom turns | stage-4 pattern: ~$7-9 | ~$7-9 |
| 4. Worst case: uncached full-res every turn | 15 × ~$1.30 | ~$20 — still inside $50 |

Verdict: scenario 3 fits with ≈ $40 headroom. Guardrails are identical to
stage 4 (batch/cheapest preferred, byte-stable prefixes, high reasoning only
on design turns, ~20-30K output caps, reasoning-token accounting after every
package, hard stop at $40 cumulative).
