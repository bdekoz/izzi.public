## 1. Decision summary

1. **Keep vendor rendering; change the production vendor to fal.ai.** fal is
   the only evaluated route that returns the actual ByteDance Seedance 2.0
   model at native 1080×1920 with a published per-second price and no
   subscription floor.
2. **Do not port the adapter directly.** Put a small vendor-neutral job
   layer between izzi's pipeline and the provider, then implement fal as the
   first adapter behind it (section 2). Switching providers afterwards is a
   config choice, not a rewrite.
3. **Canary once, before any production work:** a 10 s, 9:16, 1080p
   reference-to-video job from the Runyon Canyon opening with the
   voice-changed dialogue as the audio reference (section 4). Acceptance
   requires ffprobe-verified 1080×1920, the changed voices audibly present,
   and the charged amount matching the quote.
4. **Audio stays on eureka/ord.** The voice-change and audio-encode steps
   are local work on the two existing workers (section 3.2), not new
   provider spend.

## 2. Vendor-neutral provider layer

Goal: one canonical job shape and four verbs, so `seedance2ai.io`, fal.ai,
Replicate, Volcano Engine, or a future vendor are interchangeable without
touching the episode pipeline.

### 2.1 Canonical job spec

```json
{
  "schema_version": "izzi.video-vendor-job/1",
  "job_id": "hlt-ep10-runyon-001",
  "mode": "reference-to-video",
  "assets": {
	"image_urls": ["https://.../runyon-keyframe.png"],
	"video_urls": [],
	"audio_urls": ["https://.../runyon-10s-changed-voices.wav"]
  },
  "prompt": "...",
  "negative_prompt": ["...", "..."],
  "output": {
	"resolution": "1080p",
	"aspect_ratio": "9:16",
	"duration_seconds": 10,
	"generate_audio": true,
	"seed": 2026081601
  },
  "idempotency_key": "hlt-ep10-runyon-001-20260816",
  "cost_gate": { "max_usd": 10.0 }
}
```

The neutral spec is deliberately a superset of both providers. Each adapter
maps it onto its own contract and refuses anything its provider cannot
honor.

### 2.2 Interface (one script family, `--provider` flag)

| Verb | Contract |
|---|---|
| `vendor-quote` | job spec → estimated USD + expected delivered geometry, from a local capability/rate registry; never calls the network. Refuses jobs the provider cannot do. |
| `vendor-submit` | job spec + run dir → handle (`request_id`/`task_id`, status endpoint). Stores the raw submit response under the run dir. |
| `vendor-poll` | handle → status snapshot (queued / running / done / failed, billed units, error). |
| `vendor-download` | completed snapshot → `provider-video.original.mp4`, origin-checked per provider. |
| `vendor-verify` | downloaded file + expected geometry → ffprobe JSON + pass/fail. |

Run-dir layout is the same as the existing `build/private/seedance2-runs/`
convention (`request.json`, `submit-response`, `status-NNN`, provider
original + ffprobe), so old and new runs are auditable side by side.

### 2.3 Capability and rate registry

| Capability | seedance2ai.io (current) | fal.ai (target) |
|---|---|---|
| Native 1080×1920 | **No** — 1080p jobs deliver 720×1280 | Yes, on image-to-video and reference-to-video standard |
| Audio reference input | `media_urls` audio — untested by izzi | `audio_urls` ≤3, WAV/MP3 ≤15 MB, ≤15 s combined |
| Idempotency | `Idempotency-Key` header | None — local `request_id` + job-hash dedupe |
| Quote/balance endpoint | None | Dashboard/billing; quote from published card |
| Price model | Opaque credits | Published $/s (section 5) |
| Download origin | `cdn.seedance2ai.io` | `*.fal.media` |
| Result path | `output.video_url` | `video.url` |
| 10 s 720p clip | 110 cr ≈ $0.92, delivered 496×864 | $2.42 fast / $3.02 standard |
| 10 s 1080p clip | 240 cr ≈ $2.00, delivered 720×1280 | $6.82 standard |

The registry is the single place the price/geometry truth lives, and it is
what `vendor-quote` enforces so no job can silently exceed its cost gate.

### 2.4 Implementation path

1. Implement `fal2-submit-one.sh`, `fal2-poll-one.sh`,
   `fal2-download-one.sh` mirroring the existing
   `build/private/seedance2-*.sh` discipline (umask 077, key-file indirection,
   jq-validated bodies, origin allowlist).
2. Generalize into `build/private/video-vendor/{quote,submit,poll,download,verify}.sh`
   with adapters `adapters/{seedance2ai,fal}.sh` once the fal path is proven
   by the canary.
3. Freeze the old `seedance2-*.sh` as the historical adapter; new work uses
   the neutral layer.

Credentials stay one key file per provider under
`${IZZI_PRIVATE_DIR:-$HOME/.config/izzi/private}` (`fal.key`, `seedance2.key`),
selected by `FAL_KEY_NAME` / `SEEDANCE2AI_KEY_NAME`, never committed.

## 3. fal.ai adapter notes (ground truth, observed 2026-08-16)

| Item | Value |
|---|---|
| Endpoints | `bytedance/seedance-2.0/text-to-video`, `.../image-to-video`, `.../reference-to-video`, plus `fast/` variants |
| Auth | `Authorization: Key $FAL_KEY` (not Bearer) |
| Queue submit | `POST https://queue.fal.run/{endpoint}` → `request_id`, `status_url`, `response_url` |
| Status | `IN_QUEUE` → `IN_PROGRESS` → `COMPLETED` |
| Result | `video.url` (`v3b.fal.media`), `content_type`, `file_size`, `seed` |
| 1080p availability | I2V and R2V standard only; text-to-video schema currently stops at 720p |
| Aspect ratios | auto, 21:9, 16:9, 4:3, 1:1, 3:4, 9:16 |
| Duration | `auto` or integer 4–15 s |
| R2V references | ≤9 images, ≤3 videos (2–15 s combined, ≤50 MB, ≤720p each), ≤3 audio (≤15 MB each, ≤15 s combined); audio requires ≥1 image or video |
| Billing | 720p $0.3034/s, fast $0.2419/s, 1080p $0.682/s; video-input 0.6×; audio included either way |

Billing note: the published "token" line is the same charge restated, not an
additional fee — `tokens = h × w × (input+output s) × 24 / 1024`, and
`$0.014/1k` tokens equals the per-second rate exactly (a 10 s 1080p clip is
486 000 tokens = $6.80 ≈ $6.82). The canary verifies the invoice shows one
charge of about $6.82; if two charges appear, stop and escalate before any
further jobs.

### 4.4 The first ten seconds — proposal

Episode 10 palette: dry switchbacks, dusty ochre, dog-walker silhouettes, a
hazy basin view, and foreground bodies that occlude the vista without
obscuring captions. The opening shot is the canyon-mouth exterior pass seen
mostly from behind — the title "A View of Everyone's Back" is literal.

| Beat | Seconds | Action |
|---|---|---|
| Establish | 1–3 | Four animals in a readable staggered group on the lower switchback; one turns back as the speaker and begins, the other three visibly listen |
| Ascent | 4–7 | Unhurried climb; the dog ranges to the trail edge and returns; the cat pauses on a trail boulder; the albatross keeps one low balancing hop |
| Settle | 8–10 | Camera rests slightly below and behind the group; all four backs read against the hazy basin; breathing and tail/ear motion continue, never a frozen tableau |

Prompt (reference-to-video form):

> Animate the supplied accepted Runyon Canyon keyframe as an original
> two-dimensional graphic scene. Keep exactly one unicorn, one albatross,
> one dog, and one cat with the same readable silhouettes and restrained neon
> markings. Over ten seconds the four animals climb the dry switchback above
> the canyon mouth in a staggered group seen mostly from behind, foreground
> bodies reading clearly against a hazy Los Angeles basin in the upper third.
> The speaker turns back to the group and speaks in time with @Audio1 while
> the others listen with ear, tail, and head reactions. Show coherent leg
> cycles, shifting weight, dusty footing, and the dog ranging to the trail
> edge and returning. Keep the lower quarter of the portrait frame uncluttered
> for later captions. Environment: dusty ochre trail, chaparral sway, heat
> shimmer, two or three distant dog-walker silhouettes, one small cyan trail
> marker. Preserve bold off-white and black fields with cyan, chartreuse,
> magenta, yellow, and coral accents, tactile ink and paper texture, angular
> shadow, and generous negative space. End with all four animals intact on
> the same recognizable switchback. No text, no captions, no logos.

Negative prompt:

- static tableau
- camera-only pan or zoom
- missing, duplicate, or species-swapped animal
- extra limbs or melting anatomy
- albatross flying out of frame
- pink spike or any spike-shaped projection on an animal back
- photoreal humans or identifiable faces (background walkers stay soft
  silhouettes)
- Hollywood Sign or landmark stacking
- generic neon city or generic skyline
- embedded text, captions, logos

## 6. Risks

- **Token equivalence assumption.** If the first invoice bills per-second
  and tokens additively, the real price doubles. The canary detects this
  before any production spend.
- **T2V has no 1080p today.** The plan deliberately uses reference-to-video;
  the production port must keep all 1080p work on I2V/R2V.
- **Audio reference fidelity.** The model may restate rather than reuse the
  supplied track. Acceptance criterion 2 makes that a visible failure with a
  defined fallback (visuals + local mux), which is the pattern izzi already
  ships.
- **Keyframe schedule.** P2 is new art and needs human review; the adapter
  smoke test can proceed on the accepted Frogtown frame without waiting.
- **No Idempotency-Key on fal.** Duplicate submission protection moves to
  local `request_id` + job-hash records; the run-dir layout already supports
  this.

### 9.2 Qwen correction — what actually generates images

The user named Qwen3.8-27B as the keyframe generator. Verified 2026-08-16:
Qwen3.8-27B is a 27B dense vision-language model (image/video in, text out,

| Model | Role | Params | License |
|---|---|---:|---|
| `Qwen/Qwen-Image` | text-to-image | 20B | Apache-2.0 |
| `Qwen/Qwen-Image-Edit-2511` | image-to-image (edit/re-style) | 20B | Apache-2.0 |

use. Qwen3.8-27B still gets a slot as a zero-spend local critic: it reads a
generated frame alongside the accepted `gpt-5.6-sol-max` lineage frames and
scores cast/species/palette/linework continuity, as a first-pass filter
before the human KEEP. The generation work itself moves to Qwen-Image /
Qwen-Image-Edit-2511.
