izzi

Izzi is a C++20 header-only library for directly creating visual elements using a shrewdly-selected subset of the full Scalable Vector Graphics (SVG) standard.

It supports graphing, cartography, scientific documentation, generative design, generative art, visual thinking, physical artifact generation for large-format inkjet printers, multi-channel animation, vertical video, and web workflows.

BUILD AND EXAMPLES

make all
make clean
make examples-forms
make examples-composition

make all configures build/cmake and compiles the registered library tests and examples. make clean removes those compiled artifacts while retaining CMake configuration. make examples-forms validates native form controls and temporal behavior; make examples-composition validates authored wild scenes and crossovers. Each independently exports an HTML/SVG/PNG book and compact PDF, with source hashes and coverage receipts. Evidence lives in build/examples-study and build/examples-composition; dated PDFs live in outputs. See Building and testing for dependencies and Examples workflows for commands, selectors and output overrides.

The Meta guilloche 2 production record links the September 29 Review 4 stills, 44-page PDF and four technically verified compact reels. See the guilloche workflow for native rendering, complete-background exits and delivery checks.

PUBLISHING THE PUBLIC SITE

The public docs site (https://bdekoz.github.io/izzi.public/) is a curated snapshot of this repository: docs/, examples/, schemas/, and the root landing files, with src/ and other private trees excluded. Refresh it with:

scripts/publish-public-mirror.sh --push

Add --regen-doxygen to regenerate docs/html (with SOURCE_BROWSER = NO, source-listing pages stripped) and commit that to this repository first. Use --dry-run to build and audit the snapshot without changing any repository. The refresh also regenerates the focused Screen Glitch reference. In the snapshot, source-header links use available API pages and links to excluded local artifacts become plain labels; genuinely missing public targets still fail the audit. Dry runs use committed HEAD, so commit reviewed documentation changes before refreshing the public site. The three current workflow SVGs and their hardware inventory are copied from resources.static/workflows/ into the snapshot's docs/workflow-diagrams/; their documentation links are rewritten to those public copies.
