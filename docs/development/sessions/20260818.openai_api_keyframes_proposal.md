## 3. Scope interpretation

This round's API deliverable is **code, not images**: sol-5.6 authors a
deterministic, seed-driven izzi keyframe authoring pipeline whose output
still images match the delightful lineage's style grammar — the neon-addict
palette, background, and texture read-through that the review praised —
mapped onto each location's route geometry. Running that code to produce
the actual keyframe PNGs, and any fal.ai image-to-video render, are later
local/human-gated steps outside this round's sol-5.6 scope.

- "Delightful" is defined from the review trail: animals/background both
  reading as Neon Addict, coherent palette and texture, no Qwen-style
  brightness/warmth drift.
- All keyframe geometry stays independently authored (clean-room), exactly
  as in the guilloche/moire/surface-tension rounds; neon-addict is treated
  as a licensed visual-direction reference, never as path data to copy.
- Keyframes are stills authored before audio mux, so **the generator is
  audio-independent by construction**. The audio corpora are not required
  to generate keyframes; they are required only for the later local
  MeanVC2 mux step.

Required source assets, marked:

- neon-addict PNG set (visual direction only; sampled and resized for
  vision input);
- `data/locations.json` route points (geometry input for framing);
- the provenance-corrected accepted lineage frames (the `gpt-5.6-sol-max`
  reference the review preferred, once the §5.5 provenance items resolve).
- Not required for keyframes: all `seed-audio-*` corpora, fal provider
  outputs, and any provider-uploaded stills.

## 4. How the sol-5.6 API round would run

Same loop as the prior rounds, per the official OpenAI documentation:

- Model `gpt-5.6-sol` via the Responses API, Flex processing (`service_tier:
  "flex"`, Batch rates) with a standard-tier fallback on 429s, reasoning
  effort high on design turns and medium on mechanical edits.
- Tools: `apply_patch` for code changes and structured outputs for a
  per-package change manifest. `hosted_shell`, `code_interpreter`, and
  `image_generation` stay disabled (code changes only, no testing, no image
  production).
- Deliverable per turn: unified diffs plus a JSON manifest; a human or Codex
  applies and compiles locally.

Each work package's prompt states the policy explicitly: neon-addict and any

## 7. Compression / packaging recommendation

The billed unit is tokens, not bytes.

**Sources and routes — plain text.** The new header, example, and tests
under development are small; `locations.json` routes are a few KB of text.
Send them with `===== FILE:` separators, no compression.

**neon-addict — sample, resize, then base64.** 146 PNGs at ~2.1K×2.5K is
far more than vision needs:

- Sample about 30 plates spread across the set and resize to 1024 px on the
  long side (~960 image tokens per plate at the 32px-patch rule, ~29K tokens
  for the sample, about $0.07 per read at the Flex input rate).
- The full 146-plate set resized would be ~140K tokens (~$0.35 per read)
  with little marginal guidance; full-resolution zoom is limited to 3 plates
  per zoom turn and at most 6 zoom turns total.
- Transport: base64 data URLs for the sample; the Files API with
  `file_search` only if the same set persists across many turns.

## 8. Cost estimate against the $50 balance

Official rates for `gpt-5.6-sol` (Flex/Batch processing, per 1M tokens):
input $2.50, cached input $0.25, cache writes $3.125, output $15.00.
Reasoning tokens are billed as output tokens.

| Scenario | Math | Total |
|---|---|---|
| 1. One-shot survey | input ~40K (cache write $0.13) + output ~15K ($0.23) | ~$0.36 |
| 2. Full round K1-K4, 30 turns, cached sample | first turn ~$0.36; turns 2-30: cached read (~$0.01) + deltas ~4K ($0.013) + output ~12K ($0.18) = ~$0.20 each = $5.8; 6 zoom turns ~$0.4 each = $2.4 | ~$8.60 |
| 3. Full round with Batch/Flex for mechanical bulk | about half of the per-turn fees at half rate | ~$5-6 |
| 4. Worst case: full neon-addict set uncached every turn | 30 x (input ~$0.35 + output ~$0.30) | ~$19.50 |
| 5. Tight run: sampled, cached, Batch for bulk, 25 turns | smaller outputs | ~$4-5 |

Verdict: the recommended path (scenario 2 or 3) fits inside $50 with wide
margin; even the worst case stays below the balance. Standard-tier fallback
for Flex 429s roughly doubles per-request model fees, so prefer Flex and
retry before falling back. fal.ai image-to-video spend is a separate budget
and is outside this estimate.

Guardrails (mandatory before spend):

1. Ship the ~30-plate 1024 px sample as the default; never send the full
   neon-addict set in a turn.
2. Keep the source + reference prefix byte-stable across turns for prompt
   caching; carry `previous_response_id`.
3. Reasoning effort high only on K1/K2 design turns; medium elsewhere;
   never pro mode.
4. Set `max_output_tokens` per turn (e.g., 20K) to bound reasoning spend.
5. Use Batch/Flex for K3/K4 mechanical edits if turnaround allows.
6. Check `usage.output_tokens_details.reasoning_tokens` after every
   package; stop the round at $40 cumulative.
