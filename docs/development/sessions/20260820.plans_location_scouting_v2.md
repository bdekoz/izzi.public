## 2. Baseline

The page is a single self-contained file,
[`location.html`](https://github.com/bdekoz/situationshipin.space/blob/main/location.html),
with inline JavaScript and no framework. The catalog is
`data/locations.json`; browser edits live in `localStorage` under
`review:location-scouting:<location_id>` (catalog reviews) and
`review:location-scouting:new-draft:<slug>` (new-path drafts).

Current controls (one flex row, `flex-wrap`):

- `New path` — `.button` (primary), starts authoring a new route from an
  empty map.
- `Save path` — `.button` (primary), hidden unless authoring; requires a
  name and two or more waypoints, then writes a local draft record to
  `localStorage`.
- `Cancel` — `.button-secondary`, hidden unless a new unsaved path exists.
- `Clear saved path` — `.button-secondary`, `type="reset"`; the form
  `reset` listener deletes the `localStorage` record for the selected
  location or draft and re-renders the catalog baseline.

Two behaviors drive this change:

1. Map clicks add waypoints only in authoring mode (`authoring` is true for
   drafts and unsaved new paths, false for catalog routes). A catalog route
   such as Frogtown `start → next → final` can be dragged but not extended,
   so in-between waypoints cannot be added on the page.
2. `addPoint()` appends to the end of the marker array. There is no
   segment-aware insertion, so a click between `start` and `next` would land
   after `final` in the polyline order.

CSS (see `assets/css/review.css`):

- `.button` — background `var(--signal)` `#173a55` (dark blue), text white,
  hover/focus background `var(--focus)` `#b66a00` (orange).
- `.button-secondary` — transparent background, ink text, gray border, no
  hover color change.

## 3. Interpretation notes

The directive contains two naming and one visual inconsistency; the
assumptions below are the working interpretation and are flagged for the
human review pass.

- **A1 Button group.** "New Path to same vertical as Clear saved path" is
  read as one path-management group with `New path`, `Clear path`,
  `Revise path` in that order; `Save path` and `Cancel` remain authoring-only
  controls.
- **A2 Button label (confirmed).** The button is `Revise path`; its defined
  action sets `Decision` to `REVISE`.
- **A3 Clear path.** Clears the browser-saved path override at the selected
  location (falls back to the catalog route), then sets the review
  `Decision` to `REVISE` so a fresh path can be input. The trailing phrase
  "with any new input paths" is read as the post-clear input flow, not as
  data attached at clear time. **Confirmed by human review.**
- **A4 Save path (confirmed).** Save the current viewbox waypoints into a
  local record, then ask the reviewer to hand off: Download JSON or Open
  GitHub issue draft. No silent auto-download; the two handoff choices
  reuse the existing download/issue logic.
- **A5 Revise path.** Persists the current viewbox waypoints — including any
  newly added in-between points — into the selected location's local review
  record and sets `Decision` to `REVISE`.
- **A6 In-between insertion.** Map clicks must work for catalog routes, not
  only authoring mode, and new waypoints are inserted into the nearest
  polyline segment rather than appended, so `start → new → next` order is
  preserved. This also closes the Frogtown in-between point request from the
  2026-08-19 round.
- **A7 Visual style (confirmed).** Remove blue: `New path`, `Save path`,
  and `Revise path` all share one non-blue style — transparent background,
  ink text, gray border — with the same orange highlight on hover/focus
  (`var(--focus)` `#b66a00`, inherited from the existing Save Path hover).
  Implemented as one shared class so the three stay visually identical;
  `Clear path` and `Cancel` keep `.button-secondary` unchanged.

## 4. Proposed layout

```text
Selection
  Project   [Here Lies Trouble]
  Location  [Frogtown ...]
  Path name [............]            (authoring only)

  [New path] [Clear path] [Revise path] [Save path] [Cancel]
   primary     secondary    primary       authoring   authoring-only
```

The five buttons stay in one `flex-wrap` row so they collapse to a vertical
stack on narrow screens. `Save path` and `Cancel` keep their current
visibility rules (hidden outside authoring), so the resting view shows
`New path | Clear path | Revise path` in one row.

## 5. Button semantics

| Button | Visible | Action |
| --- | --- | --- |
| `New path` | Always | Enter authoring mode with an empty map and the path-name field; no route data is touched. |
| `Clear path` | Always (enabled when a location is selected) | Delete the `localStorage` override for the selected location (catalog fallback for catalog routes, delete draft for drafts); set `Decision` to `REVISE`; keep the name/note fields. |
| `Revise path` | Always (enabled when a route is shown) | Save the current viewbox waypoints into the selected location's local review record; set `Decision` to `REVISE`. |
| `Save path` | Authoring only | Save the current viewbox record locally, then show a handoff prompt with Download JSON and Open GitHub issue draft. |
| `Cancel` | Unsaved new path only | Discard the unsaved new path and return to the first catalog location (unchanged). |

## 6. Code-level changes (`location.html`)

1. **Markup.** Rename `Clear saved path` to `Clear path`, give it
   `id="clear-path-button"`, change it from `type="reset"` to
   `type="button"`. Add `Revise path` as
   `<button id="revise-path-button" ...>` after it. Reorder the row to
   `New path | Clear path | Revise path | Save path | Cancel`.
2. **Map click.** In `renderMap`'s click handler, allow adding points for
   catalog routes too (not only when `authoring`); keep the marker/popup
   guard.
3. **Segment-aware insertion.** Change `addPoint(lat, lng)` to find the
   nearest polyline segment and splice the new `{label: "point-N", lat,
   lng}` at that index instead of pushing; renumber labels only if the plan
   is approved to keep labels stable otherwise.
4. **Clear path.** Replace the form `reset` listener for this button with a
   `clearPath()` handler: remove `activeKey()` from `localStorage` (draft key
   for drafts), set `decision.value = "REVISE"`, re-render from the catalog
   baseline, and set the status message. The `reset` listener is removed so
   clearing no longer wipes the whole form.
5. **Revise path.** Add `revisePath()`: build a record shaped like
   `saveNow()` output with `points: currentPoints()` and
   `decision: "REVISE"`, write it to `activeKey()`, set
   `decision.value = "REVISE"`, and confirm via `status`.
6. **Save path.** Keep the two-waypoint minimum and name checks; after the
   record is persisted, show an inline follow-up prompt with two actions —
   Download JSON (Blob + temporary anchor, filename
   `<project>-<location_id or slug>.json`) and Open GitHub issue draft
   (reusing the existing issue builder) — instead of auto-downloading.
7. **Decision auto-set.** Both `clearPath()` and `revisePath()` set the
   review form select to `REVISE`; `newPathButton` keeps resetting it to
   `UNREVIEWED` when authoring starts.
8. **CSS.** Add one shared class (for example `.button-path-action`) to
   `assets/css/review.css`: transparent background, ink text,
   `var(--line)` border, and `var(--focus)` `#b66a00` hover/focus
   background and border. Apply it to `new-path-button`,
   `save-path-button`, and `revise-path-button`; leave `clear-path-button`
   and `cancel-path-button` on `.button-secondary`.
