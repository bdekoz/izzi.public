### Adapter repairs from the review

**Strict recipe loading.** Both `render-film-decay-svg.py` and
`render-film-decay-movie.py` currently call `json.loads()` before forwarding a
rewritten recipe to the native parser. Duplicate keys disappear at that step.
A recipe containing conflicting `strength` keys is rejected by the native
CLI but accepted by both Python adapters. Reject duplicates at every nesting
level before dictionary construction; keep native schema/type validation as
the contract authority. Test the actual adapter entry points.

**Whole-print duration.** The movie adapter currently requests a background
frame at presentation time even when the whole image will be replaced by a
valid retimed sample. A two-second slowed output from a one-second source
fails after the source duration, although its last planned source request is
23023/24000 seconds and all planned requests are valid.

For full-frame processing, use the planned source sample as the composition
base and eliminate the unused presentation-time lookup. For an active crop,
preserve the existing presentation-time behavior outside the crop and define
an explicit padding-tail policy, separate from the end policy for requested
source samples. Do not silently enable `hold_last` for all sampling. Preserve
zero-strength/event-bypass behavior, actual source bounds, audio timing and
the distinction between requested and encoded duration. Error cleanup must
retain the original exception and reap encoders instead of masking it with a
secondary broken-pipe error.
