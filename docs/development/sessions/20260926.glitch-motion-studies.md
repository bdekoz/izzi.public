### 2. Visual and temporal contract

1. **Damage has continuity.** A scratch or eroded region has an identity,
   lifetime, trajectory, and envelope. Tracking bands travel and recover.
   Grain and electronic noise can change each frame, with their correlation
   controlled separately. A new unrelated random mask on every frame is not an
   adequate implementation of persistent damage.
2. **Vector signal distortion is the default.** Scratches, specks, erosion
   boundaries, band displacements, ghosts, color-registration offsets, and
   noise are generated as paths/primitives or clipped/transformed vector
   groups. Clean SVG exports have transparency outside the artwork. An
   operation requiring pixel-channel filtering declares that requirement and
   is rejected in strict vector mode. Do not implement vector mode through
   `feDisplacementMap`, `feTurbulence`, or another rasterizing filter.
3. **Keep coordinates explicit.** Geometry uses normalized active-picture
   coordinates; line-based effects also declare a signal raster and field
   model. Existing pillarbox/letterbox areas are outside the active picture
   unless a preset deliberately targets the whole screen.
4. **Placement remains proportional.** Fitting a source picture or guilloche
   layer preserves its aspect ratio. Deliberate scan-line displacement belongs
   to a named glitch operation with logged parameters. It must not be hidden in
   the vector placement transform.
5. **Timing is independent of render traversal.** A document seed, effect ID,
   event ID, and absolute frame/field time determine each result. Seeking,
   resuming, and rendering chunks in a different order must reproduce it.
   Persistent events are scheduled analytically or precomputed from the seed.
6. **Declare the processing order and target.** An effect can target the source
   picture, a named vector layer, or the completed composite. Vector signal
   studies target native vector layers first. Film-damage overlays can act on
   the source picture through generated geometry/masks. A request to distort
   the completed movie must select the hybrid or raster backend explicitly.
   Any title/caption exemption is explicit.
7. **Separate recording systems from output cadence.** Support exact rational
   output rates, including 24000/1001, 25, 30000/1001, and 30 fps. PAL/NTSC
   presets declare their signal timing and field order. Export progressive
   frames by default, with documented field sampling; a 30 fps file alone does
   not establish an NTSC signal model.
8. **Preserve the audio by default.** This proposal changes pictures. Audio
   treatment, synchronization changes, and sound-design glitches require an
   explicit future track. Log stream-copy or lossless conversion choices and
   verify decoded sample identity where audio is retained.

### 3b. Process parameters and accumulated error — required follow-up

The user identifies **copy generation number** as the organizing parameter of
`vhs-generation-loss.webm`. Apply the same process-oriented reasoning to every
family: identify the repeated operation or changing physical condition, expose
that control directly, and derive the visible consequences from it. A generic
severity slider may be a preset shortcut, but it cannot replace the underlying
process parameters.

#### VHS: each generation consumes the previous result

Define generation 0 as the clean native scene. Generation 1 is one complete
copy pass. With `V_g(t)` denoting the vector scene at content time `t`:

```text
V_0(t)   = original native scene(t)
V_g(t)   = copy_pass(V_(g-1)(t), machine_profile,
                     pass_parameters[g], pass_noise(seed, g, t))
```

`generation` is an integer, with an explicit maximum set by the renderer's
complexity budget. The machine profile sets the expected loss per copy:
registration error, correlated line displacement, weighted echo spread,
stroke/paint loss, and dropout rate. Bounded per-pass variation describes
different realizations of that same copy process. Each pass can introduce new
error while retaining and further transforming the errors already present.
Changing the generation from 3 to 4 adds pass 4; it must not reroll passes 1–3.

For vector output, these are scene/paint transformations: displaced and clipped
paths, weighted duplicate paths, progressive fragmentation, and paint changes.
The optional signal backend can supply actual luma/chroma bandwidth reduction,
clipping, and encode/decode losses under the same generation contract. A single
distortion applied to the clean source with its amplitude multiplied by `g`
does not implement the requested recursive copying model.

Keep these independent axes in the interface:

| Control | Meaning |
| --- | --- |
| `content_time` | Position in the original animation or movie. Compare the same content time across generations. |
| `generation` | Number of completed copy passes. Zero is an exact identity operation. |
| `machine_profile` | Fixed transfer behavior, including expected error introduced per pass and its units. |
| `pass_variation` | Bounded variation among passes, including persistent alignment bias and time-varying error. |
| `event_age` / `event_duration` | Progress of a tracking fault, scratch, or dropout within a pass; independent of generation. |
| `seed` / `effect_id` / `pass_index` | Stable identities for repeatable error realizations. Noise is evaluated from absolute content time or field index. |
| `generation_schedule` | Exact output frame ranges assigned to integer generations in a comparison reel. |

Demonstrate generations **0, 1, 2, 4, 8, and 16** of the same short native
animation, subject to a measured resource bound. These are proposed test values,
not claims about the supplied video's labels. Hold source content and machine
profile fixed across that comparison. The main exhibit should use discrete
copy steps. Any dissolve between two generations is a separate presentation
choice with exact timing; it does not create a fractional physical copy.

#### Give the other families their own meaningful controls

| Family | Primary process parameter | What accumulates or evolves |
| --- | --- | --- |
| Film scratch / dust / fading | `wear_pass` for repeated handling/projection; `decay_age` for evolving density loss | Existing scratches and damaged regions persist, with new marks added by later passes. Separate permanent damage from transient dust and gate weave. Growth/retreat of a mask within an event has its own clock. Wear count and material aging remain distinct. |
| VHS tracking | Signed `tracking_offset` relative to the track, plus drift and lock/recovery timing | The offset controls band position/extent and dropout behavior. Replaying the same tape does not automatically add a copy generation. If a faulty playback is recorded, that pass's tracking error becomes part of the next generation's input. |
| Vertical sync loss | `sync_frequency_error`, phase, and lock/recovery envelope | Phase drift produces roll; reacquisition restores lock. Pass count alone is not the relevant control. Use declared signal timing and a separate interlace/line-pairing control. |
| Broadcast ghosting | Echo-path delays and gains; `echo_count` | Each path contributes a displaced copy. Path drift evolves over time. Repeated recording can retain ghosts, while increasing propagation-path count is a different operation. |
| Composite color artifacts | `composite_generation` and encoder/decoder profile | Repeat color registration/leakage approximations for vector output; retain prior errors through each pass. A faithful sampled decoder is an explicit future backend. Carrier phase and separation quality remain independent parameters. |
| Satellite threshold bursts | `link_margin_proxy`, fade duration, and recovery | A worsening link changes impulse/streak incidence over time. It is a reception condition, not a copy counter. Recording a degraded reception can bake those marks into a later copy pass. |

This distinction is necessary for a useful interface: **passes transform prior
results; time evolves conditions within a pass**. A preset may combine them,
but its recipe must identify both. Operation order is observable: copying an
already scratched image, damaging a new print, and mis-tracking a recording
must produce separately addressable recipes.

#### Parameter design and validation requirements

- Expose a small primary control set for each family, then a named process
  profile and optional advanced controls. Log the fully resolved values, not
  just a preset name or overall severity.
- Keep units explicit: copies/passes are integer counts, temporal controls use
  seconds or exact frame/field counts, geometric displacements use documented
  scene or scan-line units, and paint gains use defined normalized ranges.
- Derive random streams from stable effect/pass/event identities. Preserve
  already sampled pass histories when increasing the copy count. Correlation
  length and persistence are parameters distinct from error amplitude.
- Cache intermediate generations by input scene/frame, profile, pass number,
  and seed. Bound path growth; reuse vector instances and merge equivalent
  weighted echoes where possible. Any approximation must declare its tolerance
  and appear in the receipt. Exceeding a strict vector budget must report an
  error instead of silently rasterizing.
- Verify generation 0 identity and the prefix rule: rendering generation 8
  directly equals rendering generation 3 followed by passes 4–8 under the same
  settings. Seeking and parallel/chunked traversal reproduce those results.
- Compare the same source frame across copy generations and measure accumulated
  fragmentation, registration spread, and edge/paint changes. Degradation
  should trend with copy count under a fixed profile; do not require every
  individual pixel or distortion magnitude to increase monotonically, since
  signed errors can partly cancel.
- Stage 0 must label the supplied generation sequence at its actual transitions
  and align repeated source content. Stage 3 must deliver the discrete
  generation comparison, pass logs, and one combined copy-plus-tracking example
  showing how an error becomes permanent when recorded into a new copy.

### 5. Staged implementation

**Required example format:** one plate per glitch family, each exploring its
parameter space with a clearly labeled comparison grid. Hold the source scene,
content time, and seed fixed within comparisons. Use the principal parameter on
one axis and a meaningful secondary parameter or process profile on the other.
Include a clean/zero reference. The VHS plate must display actual recursive
copy generations. Produce seven separate vector plates: film damage, VHS
generation loss, VHS tracking, sync loss, ghosting, composite color artifacts,
and satellite threshold bursts. Animated demonstrations accompany these plates.

#### Stage 0 — freeze references and characterize motion

- Write `outputs/glitch-motion-studies/reference-manifest.json` with the three
  hashes, stream metadata, source-cut note, and timecoded observations above.
- Decode adjacent-frame strips around film damage at 20/40 s, tracking events
  at 8/12/24 s, and several generation-loss transitions. Measure event lifetime,
  band trajectory, color displacement, and stable versus changing regions.
- Establish active-picture bounds and determine whether the supplied decoded
  files retain field structure. Preserve uncertainty about the source capture
  chain and generation counts.
- **Exit:** each initial family has a reference interval, annotated temporal
  behavior, and an explicit mapping from observations to proposed parameters.

#### Stage 1 — deterministic contract and minimal renderer

- Add the public header, typed configuration, validator, sampler, JSON reader
  and writer, and header self-containment registration in `CMakeLists.txt`.
- Add `scripts/render-video-glitch.py` as the media adapter. Use the existing

- Establish active-picture coordinates, field/time mapping, operation ordering,

### 6. Recommendation for approval

Approve Stages 0–3 as the first implementation unit: establish the interface and
recreate the three supplied reference families. Keep Stages 4–5 in the same
roadmap, with the historical extensions sharing that interface. No model or GPU
service is required for the proposed deterministic geometry and signal
processing; benchmark the CPU renderer before adding acceleration.

The main implementation choice is the level of signal fidelity. Recommend
documented visual models first, backed by repeatable examples and measurements.
Full PAL/NTSC/RF emulation would be a separately estimated extension. Audio
remains preserved, and all random seeds and resolved motion parameters are
required in the render record.

The implemented backend is `vector_geometry`. One native example driver emits
all seven independent plates and animated studies. Each chapter compares the
same two-second source loop at six discrete settings; effect attack/release is
available separately in the API. Copy history is recursive. A three-tap vector
approximation represents accumulated echo variance and keeps path growth
bounded. Resource limits, units, fixed sampling clocks, and the resolved
polyline model are documented in the API guide.

The integration layer deliberately spans the full output height, including
the movie's gray padding. Its native active picture is a centered 1080-pixel
square, fitted proportionally from the 640-square source scene. The movie is
a separate layer and all pixels outside vector coverage remain unchanged.
This placement is recorded explicitly rather than inferred from source
letterboxing.

chain, and physical field structure remain uncalibrated. The examples label
their own known copy counts. Full raster signal reconstruction and optional
